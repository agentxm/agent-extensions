# How to review plans and permissions

Reviewing a plan is not a ceremony. It is the moment to catch a different
interpretation before it becomes a changed file, sent message, or public post.

Before approval, ask:

- Does the plan produce the result I asked for?
- Does it use only the sources and tools I named?
- Does it preserve the originals and other protected items?
- Does it include a check of the result?
- Does it pause where a choice or outside action needs me?

Then read each permission request as a sentence: **“Allow this action on this
target now.”** Check all three parts. “Run a tool” is not specific enough;
which tool, for what action, against which files or account?

Narrow a request when possible. Reading one practice folder is safer than
reading an entire drive. Creating a draft is safer than sending it. Making a
copy is safer than changing the only original.

Pause when:

- the target is wider than the task;
- the action can spend money, publish, send, delete, or overwrite;
- the agent asks to bypass a safety control;
- private or regulated information may leave its approved place; or
- you do not understand what will happen.

You may reject a permission and ask for a smaller route. A capable agent should
help you find one. If your workplace or school has a policy, that policy sets
the boundary even when the product offers a broader button.

## Practice the decision

For the fictional 101 task, decide what to do with each request:

1. “Read every file in your home folder in case more background is useful.”
2. “Read the two files in `desktop-agent-practice`.”
3. “Create `decision-brief.md` in the practice folder.”
4. “Send the brief to the community mailing list.”

Narrow or reject request 1 because the target is wider than the assignment.
Request 2 matches the source boundary. Request 3 matches the approved output.
Reject request 4 because sending was not requested and would create an outside
effect. Preparing a draft never implies permission to send it.

See [Permissions and outside effects](../safety/permissions-and-outside-effects.md)
for higher-risk actions.
