# How to check the result

A polished result can still be incomplete or wrong. Check it in four passes.

## 1. Check the assignment

Compare the output with the task brief. Confirm the audience, format, required
parts, limits, and finish checks. Mark each requirement met, missing, or
unclear.

## 2. Check the sources

Open the important source items yourself. Sample the output's key claims,
numbers, names, and dates. Ask where each came from. Missing support should be
labeled as an assumption or question, not presented as fact.

## 3. Check the changes

Review the list of files or records the agent created, changed, moved, or
deleted. If the product shows a before-and-after view, use it. Confirm that
protected originals are unchanged and that no unexpected output was left
behind.

## 4. Check usefulness and risk

Read as the intended audience. Is the result understandable? Does it hide an
important disagreement? Would acting on it create harm if a claim were wrong?
Get a qualified human review when professional or high-stakes judgment is
involved.

Ask the agent to perform its own check, but do not treat that as independent
proof. The same system that made a mistake may miss it again. Strong checks
compare the result with an outside source: the original files, a calculation,
a trusted reference, a test, or another person.

When a check fails, keep the evidence, narrow the correction, and check again.
Do not hide the failed result if someone else will depend on the work.
