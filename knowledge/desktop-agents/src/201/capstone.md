# Desktop Agent 201 capstone

A fictional community organization shares a “Monthly Update Helper” through
email. Five people have copies. Two copies use different report headings, one
quietly sends web searches containing member notes, and one requires a chart
template that was never included. The original author has left. A recent edit
improved the summary but removed the check for missing consent. No one can say
which copy produced last month's report.

Design a repair without choosing a specific management product.

## Required result

Create a workflow management plan that includes:

1. the intended users, trigger, output, and excluded uses;
2. the main maintained source and accountable owner;
3. the accepted starting version and origin of retained material;
4. every required input, companion file, tool, account, and permission;
5. a local-only or approved-search rule for member information;
6. normal, changed, missing-input, and unsafe test cases;
7. an update and rollback path;
8. a way to replace or disable the emailed copies; and
9. a short discovery description another coordinator could understand.

## Passing evidence

The plan passes when another person can locate the trusted workflow, install
or reproduce all required parts, understand its limits, identify the version
being used, run the tests, and stop or replace it without relying on the
departed author's memory.

The tool chosen later should support this operating model. Do not weaken the
model merely because a familiar tool lacks one of these controls; record the
gap and how people will handle it.
