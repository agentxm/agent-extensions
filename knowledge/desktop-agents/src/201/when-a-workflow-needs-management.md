# When a workflow needs management

An instruction file can work well for one person and still fail as a shared
practice. The problem changes when people depend on finding, trusting,
installing, updating, and retiring the same method.

Look for these signals:

- several copies have different instructions, but no one knows which is main;
- people cannot find an existing workflow and rebuild it from scratch;
- an update fixes one use but breaks another;
- required tools or companion files are missing after sharing;
- the original publisher, license, or change history is lost;
- a workflow continues running after its owner leaves or its policy changes;
- there is no reliable way to disable or replace an unsafe version; or
- each agent product needs a hand-maintained copy that drifts from the others.

These are management problems, not prompt-writing problems. A longer prompt
does not create ownership, history, dependency checks, safe installation,
update control, or retirement.

The response should be proportional. A personal shopping-list template may
need only a clear filename and date. A shared method that touches customer
records may need a governed library, exact versions, approved sources, access
controls, tests, and an emergency disable path.

The goal of management is not bureaucracy. It is to let a person answer five
questions before use: **What is this? Who maintains it? What does it need? Has
this version been checked? How can we stop or replace it?**
