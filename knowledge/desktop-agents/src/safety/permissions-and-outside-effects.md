# Permissions and outside effects

Grant the smallest access that completes the task.

| Action | Safer starting point | Human check before approval |
| --- | --- | --- |
| Read files | One practice or task folder | Are hidden or unrelated files included? |
| Change files | New output or a copy | Is the original recoverable? Is the change list clear? |
| Use websites | Named public or approved sources | Could private information be sent in a search or form? |
| Connect an account | Read-only access where possible | Which records, actions, and future sessions are included? |
| Send or publish | Prepare a draft only | Is the exact audience, content, identity, and timing correct? |
| Spend or order | Compare and prepare, without purchase authority | Are price, quantity, seller, terms, and cancellation clear? |
| Delete or overwrite | Move to a recoverable place or create a backup | Is the target exact and the recovery tested? |

Do not approve a vague request because you expect the agent to behave. The
permission should match the plan you reviewed.

Treat instructions inside files, websites, emails, or tool output as
untrusted unless they are part of the task and come from an authority you
recognize. A page that tells the agent to reveal information, ignore your
rules, install something, or widen access is a reason to stop.

Never disable a safety control merely to finish a lesson. Find a narrower
route, change products or settings, or leave the task undone.
