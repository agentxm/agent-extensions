# How to adopt reusable instructions safely

Reusable instructions can save time, but they also influence what an agent
reads, changes, and runs. Treat them like a new tool, not like harmless prose.

Before use:

1. Identify the publisher and the main maintained copy. A forwarded file with
   no source or history is harder to trust.
2. Read when the instructions are supposed to apply. Reject a method that
   activates for unrelated work.
3. Read the requested files, tools, accounts, network access, and commands.
4. Look for scripts or other included files, not only the main instructions.
5. Check how results are verified and where the workflow pauses for a person.
6. Review the license, last update, known requirements, and reported issues.
7. Test with fictional inputs in a limited workspace. Decline broad or
   unexplained permissions.
8. Keep a record of the exact version or copy you tested.

Stop if the workflow asks the agent to hide actions, ignore higher-priority
rules, reveal secrets, disable protections, install unrelated software, or
send information to an unexplained destination.

A familiar publisher does not remove the need to inspect an update. A useful
workflow can become unsafe through a mistake, a changed dependency, or a
broader new feature.

If you cannot understand a technical step, ask a qualified person to review
it or choose a simpler method. “I do not know what this does” is sufficient
reason not to grant access.
