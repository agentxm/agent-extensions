# Documentation genres

Named artifacts organizations ship — runbook, playbook, handbook, SOP, field
guide. A genre names a document's **role in an organization**; a
[type](../types/index.md) names the **reader need** its content serves. The two
are different questions, so a genre is never a fifth type: it is a container
that decomposes into one or more types.

Concepts here answer what a genre obliges an author to do *beyond* getting the
type right. Classification alone will tell you a runbook is a how-to guide; it
will not tell you the runbook needs a stop-and-escalate condition.

Genre concepts are **explainer-only**. To author one, use the guide for the
type it contains — usually [How-to guide](../types/how-to-guide.md).

The framing, including the reducibility test that decides between these two,
is in [Documentation craft](../docs-explainer.md#genres-are-not-types).

## Concepts

* [Playbook explainer](playbook-explainer.md) - What a playbook is — a
  situation-selected collection of plays plus the criteria for choosing among
  them, why that how-to/explanation fusion is deliberate, and why the boundary
  with runbook is contested.
* [Runbook explainer](runbook-explainer.md) - What a runbook is — a how-to
  guide for one known failure mode hardened for execution under a trigger, its
  automation gradient, and where it stops.
